## ۱) DNS Proxy

### چه کاری می‌کند؟

سرور تو مثل یک DNS برای کلاینت‌ها گوش می‌دهد و پرس‌وجو را به یک DNS بالادست می‌فرستد.

### فیلدهای رایج

| فیلد | مثال | توضیح |
|:---|:---|:---|
| Listen port | `53` | پورت استاندارد DNS |
| Upstream | `udp://8.8.8.8:53` | DNS معمولی گوگل |
| Upstream | `tls://1.1.1.1:853` | DNS روی TLS (DoT) |
| Listener | dns/udp یا tcp یا tls | نحوهٔ گوش دادن |

### نکته برای مبتدی روی لینوکس

پورت 53 اغلب توسط `systemd-resolved` اشغال است. اگر خطا گرفتی:

- پورت دیگری بده، یا  
- سرویس سیستمی را طوری تنظیم کن که 53 آزاد شود (با احتیاط؛ روی سرور تولید حساس است)

## ۲) TUN / TAP / TUNGO

این‌ها اینترفیس شبکه مجازی می‌سازند. اسکریپت **فقط سرویس GOST** را می‌نویسد؛ IP و route را باید خودت روی سیستم‌عامل تنظیم کنی.

| نوع | لایه | کاربرد ساده |
|:---|:---|:---|
| **TUN** | لایه ۳ (IP) | تونل در سطح IP |
| **TAP** | لایه ۲ (Ethernet) | وقتی به فریم اترنت نیاز داری |
| **TUNGO** | TUN2SOCKS | ترافیک TUN را به پروکسی/chain بفرست |

اگر نمی‌دانی TUN چیست، فعلاً از این بخش رد شو؛ برای سناریوی سنایی لازم نیست.

---

## ۳) File server

یک پوشه از دیسک را روی پورت (با listener انتخابی) مثل وب‌سرور فایل سرو می‌کند.

کاربردها:

- صفحهٔ فیک / decoy  
- توزیع فایل استاتیک  

مسیر پوشه را ویزارد می‌پرسد (یا از decoy پیش‌فرض استفاده می‌کند).

---

## ۴) Transparent redirect

| نوع | پروتکل |
|:---|:---|
| `red` | TCP |
| `redu` | UDP |

### خیلی مهم

فقط ساختن سرویس در GOST کافی نیست. باید روی لینوکس با **iptables** یا **nftables** قانون REDIRECT/TPROXY بگذاری تا ترافیک سیستم به این سرویس برسد.

اگر با فایروال لینوکس راحت نیستی، این گزینه را فعلاً استفاده نکن.
