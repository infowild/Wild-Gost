# تونل دو سرور (MWSS / Relay)

## این سناریو چیست؟

کلاسیک‌ترین Remote Port Forward:

- کاربر به **Server A** (معمولاً ایران) وصل می‌شود  
- A ترافیک را با transport رمزشده به **Server B** (خارج) می‌فرستد  
- B ترافیک را به هدف می‌دهد؛ خیلی وقت‌ها `127.0.0.1:8080` یعنی پنل سنایی روی خود B  

```text
کلاینت
   │
   ▼
A:8080  (Entry، ایران)
   │  MWSS (مثلاً روی پورت 2018)
   ▼
B:2018  (Upstream Relay، خارج)
   │
   ▼
127.0.0.1:8080  (سنایی روی B)
```

برای نسخهٔ HTTP/3 همین منطق را با [MASQUE](06-masque.md) ببین.

---

## پیش‌نیاز

1. Install روی A و B ([02](02-install.md)) — برای MWSS معمولاً Stable کافی است  
2. روی B پنل/هدف روی پورت موردنظر listen باشد  
3. فایروال B پورت Upstream را **TCP** باز کرده باشد  

---

## گام ۱ — Server B (خارج): Upstream

```text
sudo wild gost  →  2) Add  →  2) Upstream
```

پاسخ‌های نمونه برای مبتدی:

| سؤال ویزارد | نمونه | توضیح |
|:---|:---|:---|
| Name | `us` | اسم سرویس در List |
| Port | `2018` یا `443` | پورتی که A به آن وصل می‌شود |
| Handler | **Relay** | مناسب این تونل |
| Transport | **MWSS** | پیشنهادی عمومی |
| Path | `/ws` (پیش‌فرض) | باید عیناً روی A هم همین باشد |
| Auth | اختیاری | اگر گذاشتی، روی Entry هم باید ست شود |

بعد از ساخت، IP عمومی B و پورت را یادداشت کن.

---

## گام ۲ — Server A (ایران): Entry single

```text
sudo wild gost  →  2) Add  →  3) Entry single
```

| سؤال | نمونه | توضیح |
|:---|:---|:---|
| Listen port | `8080` | پورتی که **کلاینت** به آن وصل می‌شود |
| TCP / UDP | TCP | برای سنایی معمولاً TCP |
| Connector | relay | باید با handler سمت B جور باشد |
| Transport | MWSS | همان B |
| Path | `/ws` | همان B |
| Upstream address | `216.x.x.x:2018` | IP عمومی B + پورت Upstream |
| Target | `127.0.0.1:8080` | مقصد **از دید Server B** |

### نکتهٔ Target که همه اشتباه می‌کنند

Target آدرس «روی ایران» نیست.  
یعنی A به B می‌گوید: «بعد از تونل، برو به این آدرس».  
اگر سنایی روی خود B است → `127.0.0.1:8080` درست است.  
اگر هدف روی ماشین دیگری در شبکهٔ B است → IP همان ماشین را بزن.

---

## قواعد طلایی

1. **اول B، بعد A**  
2. Transport و path دو طرف یکی  
3. کلاینت فقط به **پورت A** وصل می‌شود، نه به پورت Upstream روی B  
4. ترجیحاً به‌جای دامنهٔ مشکوک، **IP عمومی B** را بزن (resolve اشتباه رایج است)  
5. بعد از ساخت: List + یک تست اتصال + Logs  

---

## تست ساده

1. از کلاینت به `IP_A:8080` وصل شو (همان تنظیمات قبلی پنل، فقط آدرس/پورت را به A بده)  
2. اگر قطع بود:  
   - B بالا است؟  
   - پورت B از اینترنت TCP باز است؟  
   - path و MWSS یکی است؟  
   - Logs روی A خطای `dial` / `timeout` دارد؟  

راهنمای عیب‌یابی: [08](08-edit-logs.md)
